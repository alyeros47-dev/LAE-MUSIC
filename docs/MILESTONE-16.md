# Milestone 16 — Financial reconciliation and operator reviews

Candidate **0.16.0-rc.16**, development branch `codex/premium-platform-release`, [draft PR #6](https://github.com/alyeros47-dev/LAE-MUSIC/pull/6). Existing website architecture, production records, approved USD prices and offline policy are preserved. No merge or Render deployment.

## Connected operator workspace

Admin → **Reconciliation** connects artist checkout reviews, Premium checkout/benefit holds, artist refund cases, Premium payment reviews, commission recoveries, finalized royalty recoveries and pending/approved withdrawals. This is an operational review of existing records, not a new financial settlement engine.

Operators can select USD or the separate historical NGN book, distinguish sandbox/live/legacy/ledger records, filter a source category, find references and page through unresolved records. Source details show the original charge currency separately from the accounting amount, link to the existing source workflow and expose a separate original-checkout provider lookup through the trusted coordinator. The queue derives attention from current source state; a resolved operator annotation cannot hide a source that needs attention again. No age cutoff silently removes old unresolved records.

Receipt cards and 30-day UTC charts keep product, currency and verified record mode separate. Gross receipts are not presented as net revenue or bank cash. Historical product receipts without independent presentment/mode evidence are labeled **legacy**, never promoted to live receipts. Finalized streaming obligations distinguish allocated royalties from releases into earned ledgers; neither means a bank payout.

The ledger preview and bounded CSV export show balanced journal movements in one accounting currency. Bank/provider mode is not inferred from generic ledger accounts. Exact minor-unit integers remain strings through the API and use BigInt formatting in the browser. Values beyond JavaScript Number precision remain exact. CSV fields are quoted and neutralize leading spreadsheet formulas, including whitespace-prefixed formulas. Ledger periods support 1–90 days; UI offers 1/7/30/90 days. Exports are capped at 1,000 records with a visible truncation notice and response header; the preview shows 12 rows and account balances at most 100 non-zero accounts. This is not an unlimited accounting archive export.

## Audited reviews without financial side effects

Claim a current source, add a note, assign it to the current operator, wait for independent evidence, or resolve the annotation after its underlying issue no longer needs attention. Each action requires a note, an exact revision and an idempotency key. Concurrent retries produce one result; stale competing edits fail instead of overwriting another operator's work.

The first source snapshot and identity are immutable. Every revision requires matching append-only review evidence. History retains actor, assignment, note, action and time, with the latest 100 events per detail response and the latest 25 reviews in the overview. The preflight checks current case/history consistency alongside financial, currency and offline-stream integrity.

Review notes cannot change receipts, prices, holds, benefits, commissions, royalty allocations, balances or withdrawal status. They cannot certify provider settlement, send funds or mark a withdrawal paid. Operators must use the existing independently verified source workflow. For example, a pending withdrawal cannot be resolved merely by writing a note; rejecting it through the existing protected withdrawal workflow releases its reserve, after which the operator annotation may be resolved. Approved withdrawals still need actual payout evidence and remain in the queue because a bank payout runtime is unconfigured.

## Authorization and database safety

Only owner and finance operators can access this workspace or export. Support/content users, artists, listeners and unauthenticated requests are denied. Named financial review writes require recent MFA and recheck authorization in their transaction, preserving existing access-revision/session-revocation fences. The transitional owner shared-key mode retains its existing boundaries; no new bypass or permanent shared credential is added. Actor identity comes from the authenticated server principal, never the request body.

Origin checks and strict field validation apply to mutations. Reference searches use parameterized SQL with literal wildcard escaping. Overview, queue, detail and export reads use repeatable-read, read-only transactions with a ten-second statement timeout. The backend does not accept a client-supplied SQL table or financial account mutation. Review annotations never call an external provider or send a message. A separate **Verify original provider record** action is limited to existing artist/Premium checkout sources: it derives the account owner from the database and reuses the existing independently verified coordinator, account/mode matching, duplicate-receipt protection, authorization fence and cross-process cooldown. It does not initialize another charge or accept an operator-supplied payment result. Only independently matched provider evidence can fulfill an existing purchase through that original coordinator. Provider lookup remains safely unavailable when the reviewed sandbox account is unconfigured; no live-money runtime is enabled.

Additive migration **016-reconciliation-reviews.sql** creates case/event history, immutable identity/revision guards, a deferred matching-event constraint and attention/journal-date indexes. Earlier migration files and commercial terms are unchanged. Test a sanitized production clone before deployment and measure index/migration duration on real table sizes. No production clone or load/query-plan verification was available in this environment. Retain the additive history and constraints during a compatible rollback; do not delete review or financial records.

Real R2/music/email, the dedicated offline signing key, approved free-listener ad creative, production-clone migrations/load/backup/recovery, physical devices and manual accessibility review remain outstanding.
