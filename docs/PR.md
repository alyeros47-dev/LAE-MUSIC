LAE-MUSIC had disconnected page styles and recreated playback on navigation. This draft adds a shared premium dark interface, persistent real-source player and connected discovery, listener, artist, studio, partner, account and admin workspaces while preserving the existing Node/PostgreSQL/R2 architecture and legacy compatibility routes.

Completed connected features include durable private studio-release copying, leased retries, owner previews and explicit publication; notification outbox delivery; revision-protected playlist management; stable filtered discovery pagination; atomic generation/lyrics/gift operations; guarded uploads and annual quotas; free affiliate registration with approved product-sale commissions; and protected reporting, content controls and withdrawals with the existing 3% fee.

The purchase/accounting milestone adds immutable server-priced orders, artist review/history/cancellation, active and future renewal terms, provider-neutral raw-byte verification plus independent payment lookup, atomic verified subscription/studio-credit fulfillment, pending commission journals, auditable receipts/review events and admin reconciliation. Database constraints protect journal uniqueness and entitlement ownership. No provider adapter is configured in production: checkout, public payment webhooks, commission clearance and bank payouts remain disabled. Legacy demo accrual, activation and withdrawal mutations are permanently disabled; historical records remain readable. No real payment success is simulated. Production records were not accessed or reset; no Render deployment or production merge was performed.

The selected gateways are Flutterwave and Paystack. USD remains the accounting/product currency, with country-based display defaults, manual currency override, timestamped local estimates, honest USD fallback and uninterrupted playback. Reference snapshots and local checkout quotes are immutable. Prepared provider adapters follow their documented webhook/amount conventions, including Paystack XOF units and the distinction between Flutterwave v3 and v4. No merchant account, checkout coordinator, local settlement bridge or live gateway is activated by this draft. `docs/MILESTONE-4.md` documents the precise boundary and source references.

Validation: local `npm test` passes 89 behavioral/contract cases, 25 existing mocked Sonic cases, 31 source invariants and integrity checks. [CI run 40195809624](https://github.com/alyeros47-dev/LAE-MUSIC/actions/runs/40195809624) passes HTTP checks, desktop/tablet/mobile journeys and 32 tests against disposable PostgreSQL 16 (migrations 001–005). This includes signed-fixture provider verification, exact amounts, immutable FX quotes, source outage/staleness, playback during currency changes and prior concurrency/renewal/commission/credit/refund regressions. Country-selector accessible labels found in the first browser run were corrected before passing runs. Local-price screenshots were inspected at all three sizes. All gateway, FX, media and music-provider test services are isolated fixtures; live account/feed verification remains outstanding.

This is not launch-ready. See `docs/RELEASE.md` for evidence and remaining gates, `docs/MILESTONE-2.md`, `docs/MILESTONE-3.md` and `docs/MILESTONE-4.md` for exact feature/integration boundaries, `docs/AUDIT.md` for preserved commercial contradictions, and `docs/DEPLOYMENT.md` for staging/migration/rollback procedures. Live gateway checkout/settlement/refunds/disputes, funded royalty rules, bank payouts, real R2/music provider verification and a sanitized production-schema upgrade are still required before commercial launch.
