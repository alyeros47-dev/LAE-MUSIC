## Storage and access

- Dedicated P-256 server signing key, account-owned P-256 browser device identity and AES-256-GCM media encryption. Browser private/AES keys are nonextractable CryptoKeys stored in IndexedDB, not localStorage or public caches. Actual plaintext is used only for the native audio element's temporary Blob and its buffer is cleared after Blob creation.
- Signed grants last at most **24 hours**, capped by Premium expiration. Reconnection revalidates the owned account, active term, review/refund holds, song publication and device revocation. Offline expiration/clock checks run during playback and before resume; access loss pauses and clears the audio source and revokes Blob URLs. Sign-out/account changes remove local audio/metadata/keys and attempt online device revocation.
- Saving uses a one-use, owner-checked five-minute POST media ticket. R2 fetching is server-owned, bounded, MIME/length checked, redirect-disabled and never accepts a client-supplied remote URL. Audio and authenticated APIs have no-store semantics and are excluded from the service-worker cache.
- The worker caches only the branded offline shell, player/CSS/modules and own public artwork. `/offline` starts without network access. Existing push handlers are retained; activation does not reload or interrupt the shared player. No ordinary file-download button/link is created.
- Browser limits: 20 MiB/song, 250 MiB/library, 100 songs and three active devices/account. Device removal and saved-song deletion are available in the library. Atomic IDB operations and Web Locks (with an IDB lease fallback) protect cache/sync operations. Storage persistence is requested when supported; it is not guaranteed.

## Accounting and fraud controls

Actual local listening signals require at least 30 seconds of plausible uninterrupted playback. Seeks, long timing gaps, hidden-tab suspension and playback source changes cannot simply add elapsed wall time. Events are signed using server-issued, single-use action challenges and carry unique IDs, strictly ordered device sequences, grant IDs and time bounds. Sync verifies ownership and payload signatures, rejects conflicting IDs, rolls back malformed batches, and deduplicates retries before inserting any eligible stream. Old valid events can sync after the subscription expires only if the original play was covered and received within **48 hours**. Late/invalid/held/self/repeated/overlapping/capped/closed-period events are retained with rejection reasons, without a qualifying stream.

One qualified offline event creates one existing Premium playback/stream and one catalog engagement record, never a direct cash credit. Existing repeat and daily limits span online/offline sources. Source/evidence references remain immutable. Offline plays share the existing funded **50% recognized-net Premium revenue pool**, original currency books, exclusions, monthly review and refund recovery. No extra royalty money, purchases or commissions are invented. Finalization waits until **48 hours after UTC month-end** so timely offline reports can arrive; a reviewed statement cannot be silently reopened. Admin → Royalties shows offline validation totals, and read-only preflight verifies eligible event/stream bindings.

The device proof protects identity, replay and casual tampering; it does not prove a human listened. A browser owner can inspect/modify client code, attempt to use nonextractable keys through the browser, or record audible output. Browser storage is **not DRM**. Online fraud review/exclusions and the fixed funded pool remain essential. Instant revocation while completely disconnected is impossible; the signed maximum 24-hour lease bounds access until reconnection.

## Verification scope

The application suite passes 146 checks, the actual PostgreSQL 16 suite passes 141, socket HTTP passes one and real-library loopback SMTP/TLS passes four. Automated results and final counts are recorded in RELEASE.md and `artifacts/offline-test-results.txt`. PostgreSQL tests execute real migrations/constraints, concurrent retries, ownership/nonce/media protection, immutable events, sequence rollback, expiry/grace, late synchronization and payment holds. Application tests also verify actual server ECDSA/Web Crypto signature compatibility, media bounds, approved-ad guard behavior and Premium ad exclusion.

Chromium desktop/mobile tests use actual service-worker installation and control, reload while network-disabled, real IndexedDB and nonextractable CryptoKeys, AES cipher tamper rejection, a native audio element playing a 90-second isolated WAV for 31 real seconds, unique synchronization, expiry, clock rollback and account cleanup. A feature-disabled browser receives an honest unsupported message. The existing three-viewport/27 axe journeys run in the same browser command. These tests use fixture R2/payment/account responses; they are not real gateway, live subscription or R2 account verification.

Firefox, Safari/iOS, physical phones, background playback and low-storage eviction are **not verified** by Chromium emulation. Browser codec support varies by source format. Private browsing, disabled storage, unsupported key persistence, quota or site-data clearing can disable/remove saves. Safari installed PWAs can have separate storage; browser migration/origin changes do not transfer a library. Mobile OS suspension delays sync; unreported plays after the 48-hour deadline cannot be counted retroactively. Users must first connect to save and verify access, then reconnect at least every 24 hours. The app is not a promise of indefinite offline access.
