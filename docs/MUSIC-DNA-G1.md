# G1 — Deep Worship & Spiritual Encounter

Instruction Package 2 supplies five approved profiles. They are integrated on the
existing `codex/music-dna-foundation` branch together with the foundation batch.
This is one supplied research group from the expected 43-group programme, not
five research groups or a completed international catalogue.

| Style ID | Customer-facing name | Tempo | Defining direction |
| --- | --- | --- | --- |
| G1-01 | Glory Trumpet Worship | 68–82 BPM | Gentle 4/4; warm piano, expressive trumpet and choir; trumpet interlude and powerful concluding chorus |
| G1-02 | Heavenly Fire Worship | 78–105 BPM | Reflective opening, controlled live-drum fills, expressive electric guitar, progressive build and full-band climax |
| G1-03 | Broken Before You | 58–76 BPM | Intimate grand piano and warm strings; minimal percussion, emotional bridge and final chorus; no dance shift |
| G1-04 | Altar Encounter | 55–78 BPM | Prayerful atmospheric keys, ambient guitar and breathing room; optional free-time introduction; reverent resolution |
| G1-05 | Intimate Acoustic Worship | 62–88 BPM | Fingerpicked guitar, soft piano, warm bass, subtle shaker and delicate harmonies; acoustic passage before final chorus |

`config/music-dna.json` preserves each supplied mood, instrument family, arrangement
and lyric themes. Technical vocal/mixing guidance and variation choices instantiate
those supplied directions; they do not create extra styles or request imitation.
All delivery descriptions are gender-neutral. Voice, supported custom profile and
language choices use the existing independent controls and owner checks.

Each option displays its supplied professional name. The selected option shows a
short explanation. The department/category is an `optgroup` heading, not a song
style or selectable category ID. The other departments have no fabricated options.

Internal research references exist only in the server catalogue's research field.
Public metadata, provider profile instructions and stored snapshots exclude them.
Validation prevents reference names appearing in another public style/category and
rejects generated references across the catalogue, not only the selected profile.
This is not a request to reproduce a recognisable voice, recording, melody or lyric.

Variation choices remain within the user's directions: trumpet phrasing and
transitions for G1-01; controlled fills/refrain/climax timing for G1-02; piano
voicings, strings, melody and imagery for G1-03; atmosphere, refrain placement,
phrasing and harmonic movement for G1-04; guitar picking/voicings, melodic phrases
and chorus arrangement for G1-05. English production prompts are checked for the supplied core instrumental terms,
including explicit trumpet, electric guitar, piano/strings, ambient prayer textures
or fingerpicked acoustic guitar as appropriate. Echoing correct style/mood metadata
with an unrelated generic or neighboring prompt is rejected through the existing
credit-restoration path. The selected lyric languages remain independent of the
English production instructions. Every profile also retains the existing duration
and production-prompt limits. No unverified provider seed parameter is introduced.

Tests exercise all five profiles across neutral/male/female/duet/custom voices,
all six initial languages and multilingual combinations, fixed mood/instrument
identity, bounded variation and retry stability. Tests invoke the actual lyrics
handler for all five profiles with mocked approved GPT responses, and verify
credit reservation/refund behavior and ready-custom-voice ownership checks.
Real disposable PostgreSQL tests save each G1 provenance snapshot and its upload
code, verify replay and consume exactly five reserved lyric credits for five
completed requests. Existing concurrent duplicate/refund and immutable-history
checks remain in place.

Browser journeys select all five real G1 options and their descriptions, preserve
a duet and English/French selection through reload, verify no mood control, and
send the G1 selection through the existing lyrics form. Additional synthetic
catalogue tests remain explicitly separate from the supplied G1 content.

Provider responses in automated tests are mocked. No paid audio requests,
production data changes or R2 mutations are needed for these checks. Actual
musical/linguistic quality and audio-generation acceptance require controlled
provider tests; textual metadata checks alone do not establish audio quality.
